# Reproducibility Package

Frenkel-Ladd-Anchored Thermal Backbone Learning for Admissibility-Aware Free-Energy Reconstruction under Descriptor Aliasing

o This repository contains the minimum processed dataset, analysis scripts, representative output tables, and representative LAMMPS input files required to reproduce the principal numerical results reported in the manuscript and Supplementary Information.

o The package is intended for reproducibility of the Frenkel-Ladd-anchored thermal-backbone / Backbone Ridge workflow, including Ti-domain reconstruction, grouped validation, stricter hold-out tests, negative-control transfer analyses, and external Al/Cu transfer.

o Reproduction starts from processed snapshot-level data. Large raw MD trajectories, restart files, and production dump files are not included.

o Some filenames retain the historical `piml` prefix for compatibility with the analysis workflow. These filenames refer to the retained Backbone Ridge implementation described in the manuscript and do not indicate a separate production model.

2. Processed Data and Required Input

----------------------------------------------------------------------

Python_Codes/table/

o Contains the processed snapshot-level input dataset and representative CSV output tables generated by the analysis scripts.

o The repository is designed so that reproduction of the statistical-learning and validation workflow can start directly from the processed dataset in this folder.

o The principal external processed input required by the supplied downstream analysis scripts is:

- F0_dF_by_snapshot.csv

o For direct execution of the scripts, this file should be located at:

Python_Codes/table/F0_dF_by_snapshot.csv

o The processed table contains the thermodynamic and descriptor information required by the retained Backbone Ridge workflow.

o The complete manuscript dataset contains the Ti-domain systems:

- alpha-TiAl
- beta-TiV
- stacked Ti64

and the external transfer systems:

- FCC Al
- FCC Cu

evaluated over the temperature states considered in the manuscript.

o The processed dataset provides the quantities required for construction of the physics baseline, Frenkel-Ladd reference, system-specific gauge alignment, gauge-fixed residual, thermal backbone, and descriptor-dependent correction.

o Representative output tables are included to allow direct comparison between newly reproduced results and the manuscript/Supplementary Information.

o Original MD dump trajectories are not required for the downstream processed-data analysis.

o Large raw MD trajectory files, restart files, and production dump files are not included.

o Their filenames are intentionally retained as stable pipeline-level names because they are shared by multiple downstream analyses.

4. Main Analysis Scripts

----------------------------------------------------------------------

run_piml_core_pipeline_backbone.py

o Main production implementation of the retained Frenkel-Ladd-anchored thermal-backbone / Backbone Ridge workflow.

o The absolute free-energy reference is represented hierarchically as:

F_ANC = F0 + C_s + DeltaF_res

with:

DeltaF_res = g_hat(T) + r_hat(delta x)

where:

- F0 is the explicit physics baseline
- C_s is the system-specific gauge alignment
- g_hat(T) is the common thermal backbone
- r_hat(delta x) is the anchor-relative descriptor-dependent Ridge correction

o The final reconstructed free energy is:

F_hat = F0 + C_s + g_hat(T) + r_hat(delta x)

o The script performs:

- construction of gauge-fixed residual targets
- construction and fitting of the common thermal backbone
- anchor-relative descriptor preprocessing
- Ridge-model selection
- grouped out-of-fold validation
- admissibility-aware evaluation
- final Ti-domain fitting
- Ti-domain reconstruction
- no-retraining external Al/Cu prediction
- generation of downstream prediction tables

o Representative outputs include:

- piml_model_selection_summary.csv
- piml_metrics.csv
- piml_predictions_Ti.csv
- piml_predictions_Al.csv
- piml_predictions_Cu.csv
- piml_feature_audit.csv
- piml_backbone_coefficients.csv

--------------------------------------------------

run_sample_sufficiency_backbone.py

o Evaluates robustness of the retained Backbone Ridge workflow under reduced training snapshot counts.

o Subsampling is performed within the Ti-domain system-temperature groups, after which the production workflow is reevaluated.

o Representative outputs include:

- table_s12_sample_sufficiency.csv
- sample_sufficiency_runs.csv
- sample_sufficiency_audit.csv

o `table_s12_sample_sufficiency.csv` corresponds to the sample-sufficiency analysis summarized in Supplementary Table S12.

--------------------------------------------------

run_repeated_training_backbone.py

o Repeats the retained Ridge model-selection and fitting workflow as an execution/pipeline reproducibility audit.

o Because the retained Ridge and grouped-cross-validation workflow is deterministic, agreement across nominal seeds should be interpreted as computational/pipeline reproducibility rather than stochastic-training uncertainty.

o Representative outputs include:

- table_s13_repeated_training_summary.csv
- repeated_training_runs.csv
- repeated_training_audit.csv

o The summary output corresponds to the repeated-training stability analysis reported in Supplementary Table S13.

--------------------------------------------------

run_logo_holdout_backbone.py

o Performs Leave-One-Group-Out validation across Ti-domain system-temperature groups.

o The analysis evaluates whether the retained formulation preserves reconstruction accuracy and thermodynamic ordering when individual system-temperature groups are excluded from model fitting.

o This is an anchor-aligned Ti-domain LOGO evaluation and should not be interpreted as an anchor-free blind-material prediction test.

o Representative outputs include:

- table_s17_logo_holdout.csv
- logo_holdout_runs.csv
- logo_holdout_audit.csv

o `table_s17_logo_holdout.csv` corresponds to the LOGO analysis reported in Supplementary Table S17.

--------------------------------------------------

run_stricter_split_backbone.py

o Performs stricter internal validation beyond the standard grouped-OOF / LOGO evaluation.

o The script evaluates four additional split designs within the Ti-domain:

- leave-one-system-out
- bulk-to-interface transfer
- leave-one-temperature-out
- low-to-high temperature transfer

o Representative outputs include:

- stricter_system_holdout_runs.csv
- stricter_system_holdout_summary.csv
- stricter_bulk_to_interface_runs.csv
- stricter_bulk_to_interface_summary.csv
- stricter_temperature_holdout_runs.csv
- stricter_temperature_holdout_summary.csv
- stricter_low_to_high_runs.csv
- stricter_low_to_high_summary.csv

o Additional prediction and audit files may include:

- stricter_system_holdout_predictions.csv
- stricter_state_mean_predictions.csv
- stricter_temperature_holdout_predictions.csv
- stricter_bulk_to_interface_predictions.csv
- stricter_low_to_high_predictions.csv
- stricter_split_audit.csv

o Supplementary Table S18 is constructed from the leave-one-system-out and bulk-to-interface results.

o Supplementary Table S19 is constructed from the leave-one-temperature-out and low-to-high-temperature transfer results.

o Separate combined `table_s18_*` and `table_s19_*` CSV files are not required because the constituent results are reported directly by the corresponding summary files.

--------------------------------------------------

run_ti_trained_controls_transfer.py

o Evaluates deliberately restricted negative-control models under the same Ti-training to Al/Cu no-retraining evaluation hierarchy used for the external transfer analysis.

o The script evaluates restricted models designed to test whether the reported behavior can be reproduced using substantially reduced information.

o The retained controls include:

- a temperature-only control
- a temperature plus local-response control

o The control models are trained using the Ti-domain information and evaluated on the external Al/Cu systems without retraining under the transfer protocol described in the manuscript.

o Required generated inputs are:

- piml_predictions_Ti.csv
- piml_predictions_Al.csv
- piml_predictions_Cu.csv

o These files must therefore be generated by the core pipeline before this script is executed.

o Representative outputs include the corresponding control predictions, system/temperature summaries, ordering summaries, transfer comparisons, and audit information.

5. Post-Processing Scripts

----------------------------------------------------------------------

postprocess_piml_ti_domain.py

o Reads:

- table/piml_predictions_Ti.csv

o Generates manuscript-facing Ti-domain reconstruction and thermodynamic-ordering summaries for:

- alpha-TiAl
- beta-TiV
- stacked Ti64

o Representative outputs include:

- fig7_ti_ordering_inputs.csv
- piml_ti_means_by_system_T.csv
- piml_ti_ordering_global.csv

o These outputs provide the processed quantities used for the Ti-domain reconstruction and ordering analyses associated with the corresponding main-text results.

--------------------------------------------------

postprocess_piml_al_cu_transfer.py

o Reads:

- table/piml_predictions_Al.csv
- table/piml_predictions_Cu.csv

o Generates temperature-resolved external-transfer summaries for:

- FCC Al
- FCC Cu

o Representative outputs include:

- piml_al_summary_by_T.csv
- piml_cu_summary_by_T.csv
- fig8_transfer_inputs_combined.csv
- fig8_al_transfer_inputs.csv
- fig8_cu_transfer_inputs.csv

o The `fig8_*` files provide the processed transfer quantities associated with the external Al/Cu results in Fig. 8.

--------------------------------------------------

summarize_residual_metrics.py

o Reads the retained Ti/Al/Cu prediction tables and generates aggregated residual-learning and staged absolute-reconstruction summaries.

o The staged reconstruction separates:

1. minimal physics baseline:

F0

2. gauge-aligned baseline:

F0 + C_s

3. thermal-backbone reconstruction:

F0 + C_s + g_hat(T)

4. final Backbone Ridge reconstruction:

F0 + C_s + g_hat(T) + r_hat(delta x)

o Representative outputs include:

- residual_predictions.csv
- residual_summary_by_system_T.csv
- residual_summary_by_system.csv
- residual_summary_global.csv
- residual_summary_audit.csv
- reconstruction_stage_summary_by_system_T.csv
- reconstruction_stage_summary_by_system.csv
- reconstruction_stage_summary_global.csv

o These files support the staged-reconstruction summaries reported in the manuscript and Supplementary Information.

o Any combined residual-model comparison generated by this utility should be interpreted as a diagnostic summary rather than as a global machine-learning model leaderboard, because the retained production model and auxiliary comparison models do not necessarily share identical training and evaluation protocols.

6. Descriptor Utility

----------------------------------------------------------------------

utils_structure_descriptors.py

o Provides utility routines for constructing snapshot-level structural descriptors from compatible LAMMPS dump files.

o The distributed `F0_dF_by_snapshot.csv` has already been processed.

o Therefore, this utility is not required for reproducing the downstream Backbone Ridge, validation, control, or transfer analyses from the distributed processed dataset.

o Raw descriptor generation requires compatible upstream LAMMPS trajectory/dump files containing the expected per-atom quantities.

o These large raw trajectory files are not included in the minimal processed-data reproducibility package.

o The optional `freud-analysis` package is required only when the corresponding q6 descriptor-generation functionality is invoked.

9. Recommended Reproduction Workflow

----------------------------------------------------------------------

Before running the scripts:

cd Python_Codes

o Confirm that the processed input file is available at:

table/F0_dF_by_snapshot.csv

--------------------------------------------------

Step 1

o Run the production Backbone Ridge workflow.

python run_piml_core_pipeline_backbone.py

o This step generates the Ti/Al/Cu prediction files required by several downstream analyses.

--------------------------------------------------

Step 2

o Evaluate sample sufficiency, execution reproducibility, and grouped hold-out robustness.

python run_sample_sufficiency_backbone.py

python run_repeated_training_backbone.py

python run_logo_holdout_backbone.py

--------------------------------------------------

Step 3

o Run stricter structural and temperature split analyses.

python run_stricter_split_backbone.py

--------------------------------------------------

Step 4

o Run the restricted negative-control transfer analyses.

python run_ti_trained_controls_transfer.py

o This step requires the `piml_predictions_Ti.csv`, `piml_predictions_Al.csv`, and `piml_predictions_Cu.csv` files generated in Step 1.

--------------------------------------------------

Step 5

o Generate manuscript-facing Ti-domain, external-transfer, and staged-reconstruction summaries.

python postprocess_piml_ti_domain.py

python postprocess_piml_al_cu_transfer.py

python summarize_residual_metrics.py

--------------------------------------------------

o Generated CSV files are written to:

Python_Codes/table/

12. Data and Reproducibility Scope

----------------------------------------------------------------------

o This repository contains the processed dataset, analysis scripts, representative output tables, and representative upstream simulation inputs required to reproduce and verify the principal processed-data numerical analyses reported in the manuscript and Supplementary Information.

o The package supports reproduction of:

- Backbone Ridge model selection and fitting
- gauge-aligned residual reconstruction
- Ti-domain grouped out-of-fold evaluation
- sample-sufficiency analysis
- repeated-execution robustness
- LOGO evaluation
- leave-one-system-out validation
- bulk-to-interface transfer
- leave-one-temperature-out validation
- low-to-high-temperature transfer
- external Al/Cu no-retraining transfer
- restricted negative-control transfer analyses
- staged free-energy reconstruction
- manuscript-facing summary tables

o Large MD trajectory files, restart files, and production dump files are not included because the public package is designed around the processed-data reproducibility layer.

o Representative LAMMPS input and configuration files are provided to document the upstream simulation workflow.

o Reproduction of the downstream statistical-learning and validation results does not require regeneration of the complete raw MD trajectories.

13. Notes on File Naming

----------------------------------------------------------------------

o Several files retain the historical `piml` prefix for compatibility with the development and manuscript-analysis workflow.

o These filenames refer to the retained Backbone Ridge implementation and should not be interpreted as a separate production model.

o Pipeline-level intermediate files such as:

- piml_predictions_Ti.csv
- piml_predictions_Al.csv
- piml_predictions_Cu.csv

retain semantic filenames because they are shared by multiple downstream scripts.

o Manuscript-facing output files use the current Supplementary Table or main-text Figure numbering where appropriate.

o If manuscript figure or table numbering changes during subsequent editorial processing, the numerical content of the corresponding CSV files remains unchanged.
